UNDER THE SCALES

How a dragon is forged

The website runs the exact same pipeline as the Rust action — collect, stage, coat, animate — just in your browser.

STEP 1

Collect

Public contribution calendar (jogruber API), profile and repos (GitHub REST). All CORS-enabled, all fetched straight from your browser.

STEP 2

Stage

The annual contribution window — plus current month, whichever is larger — picks one of six evolution stages.

STEP 3

Coat

Top three languages by repository count tint three zones. Dark colours are lifted so the outline stays readable; mixed profiles keep more emerald.

STEP 4

Animate

A seamless 48-frame loop: three wing flaps, two blinks, one fire breath, rising embers and twinkling stars for legends.

WHY IT'S COOL

Built like the real thing

Not a re-drawing — the actual hand-finished sprite layers, tinted and composited with the same math as the Rust renderer.

🎨

Real sprites, real tinting

The 16 layered PNGs from the action are colorized in-browser with the same HSV rules: green zones → primary, warm cream → belly or horns.

🧮

Faithful port

Stage thresholds, streak math, coat strengths, nearest-neighbour rotated wing blits, deterministic noise — ported line-for-line from Rust.

⚡

Zero backend

Every API used is CORS-enabled. GitHub Pages serves static files; all fetching, counting and rendering happens on your machine.

🔥

Procedural fire

The flame is drawn pixel-by-pixel from a sine envelope and a hash-noise flicker — no image assets, just like the original.

📦

Offline-ready demos

Bundled snapshots for all six stages mean the site always hatches something — even when GitHub rate-limits or you're offline.

🧬

Deterministic

Same username, same dragon. No randomness anywhere — the loop is seamless and the stills are reproducible.

QUESTIONS

      
FAQ

    

    

      

        Why is my dragon still an egg?
        
The stage uses the current calendar year window (it resets every January 1st) — the same rule as the action. Contributions from last year don't count. Keep committing and watch it grow. If this month alone beats the year total, the month wins (that's the max(total, monthly) rule).

      

      

        Is my data safe? What's sent where?
        
Everything happens in your browser. The site fetches public data from GitHub's REST API and the public contributions API, computes the stage, streaks and language coat locally, and renders on a canvas. Nothing is stored, logged or proxied.

      

      

        Why does my dragon look slightly different from my profile GIF?
        
The action can use GitHub's GraphQL colours and your exact repository list with a token; the website uses the tokenless REST path with an offline Linguist colour table, so a tint may differ by a shade. Stage, animation and effects are identical.

      

      

        Why did it say the language data (repo API) was unavailable?
        
GitHub's tokenless REST API allows 60 requests per hour per visitor IP — shared networks, VPNs and offices burn through that quickly. When it's exhausted your dragon still hatches (stage, streaks and animation come from the contributions API), but the language coat falls back to the classic emerald. Results are also cached in your browser for an hour, so re-checking the same user costs nothing.

      

      

        I hit "Generate" and got an error.
        
Check the spelling (letters, numbers, dashes) and that the account exists. If the contributions API is unreachable from your network, wait a moment and retry — or explore the bundled demo snapshots (egg, adolescent, legendary…) which always work offline.

      

      

        Can I get a GIF like the action produces?
        
The browser port animates on canvas and exports PNG stills and a 1280×640 share card. For an embeddable GIF that updates itself, add the git-dragon action to your profile repository — the Embed section has the ready-made workflow.
